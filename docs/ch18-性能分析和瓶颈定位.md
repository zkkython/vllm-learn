# 课时18 - vLLM 性能分析和瓶颈定位

> **关键源码文件**：
> - `vllm/vllm/config/profiler.py` -- `ProfilerConfig`，定义 torch/cuda profiler 的配置项
> - `vllm/vllm/profiler/wrapper.py` -- `TorchProfilerWrapper`、`CudaProfilerWrapper` 与 profiler 生命周期管理
> - `vllm/vllm/profiler/layerwise_profile.py` -- layerwise profile 数据结构、树化统计与表格导出
> - `vllm/vllm/profiler/utils.py` -- profiler 结果格式化与事件树工具
> - `vllm/vllm/config/observability.py` -- `enable_layerwise_nvtx_tracing` 等可观测性配置
> - `vllm/vllm/utils/nvtx_pytorch_hooks.py` -- NVTX hook，负责为模块执行打输入/输出范围标记
> - `vllm/vllm/v1/worker/gpu_worker.py` -- worker 侧 profiler 初始化、step、annotation 和 start/stop 入口
> - `vllm/vllm/entrypoints/llm.py` -- `LLM` 入口接受 `profiler_config`

## 学习目标

1. 理解 vLLM 当前仓库中 PyTorch Profiler、CUDA Profiler、NVTX 埋点这三类分析手段的边界

3. 理解 `layerwise_profile` 如何把 Kineto 事件树还原成按模块聚合的统计视图
4. 掌握利用 NVTX + Nsight Systems 观察 vLLM worker 迭代、层级执行和 GPU 时间线的基本方法
5. 能够根据源码判断应该用哪种 profiler 来定位哪一类瓶颈

## 18.1 vLLM 使用 PyTorch Profiler 进行分析

### 原理讲解

PyTorch Profiler 适合回答的问题通常是：

1. **这一轮迭代里 CPU/GPU 时间花在哪些算子上？**
2. **不同 op 的 self time / total time 是多少？**
3. **哪一层、哪一类 kernel 占了最多 CUDA 时间？**

它的优势是：

- 与 PyTorch runtime 深度集成
- 支持 CPU/CUDA 双视角
- 可以导出 TensorBoard trace
- 可以做 layerwise 聚合

它的劣势是：

- 开销通常高于纯系统级工具
- 对超长时间窗口和全系统视图不如 Nsight Systems

### 源码解析

**1. `ProfilerConfig` 定义了 torch profiler 的关键开关**

`config/profiler.py` 里最重要的字段有：

```python
profiler: "torch" | "cuda" | None
torch_profiler_dir: str
torch_profiler_with_stack: bool
torch_profiler_with_flops: bool
torch_profiler_record_shapes: bool
torch_profiler_with_memory: bool
delay_iterations: int
max_iterations: int
```

这些配置基本对应了三个维度：

- 存到哪里
- 采哪些信息
- 何时开始、何时停止

**2. worker 侧真正用的是 `TorchProfilerWrapper`**

在 `v1/worker/gpu_worker.py` 的初始化中：

```python
if profiler_config.profiler == "torch":
    self.profiler = TorchProfilerWrapper(
        profiler_config,
        worker_name=worker_name,
        local_rank=self.local_rank,
        activities=["CPU", "CUDA"],
    )
```

所以一旦启用 torch profiler：

- worker 会同时记录 CPU 和 CUDA 事件
- trace 会保存到 `torch_profiler_dir`

**3. `TorchProfilerWrapper` 封装了 start/step/stop**

核心包装在 `profiler/wrapper.py`：

```python
self.profiler = torch.profiler.profile(
    activities=[...],
    record_shapes=...,
    profile_memory=...,
    with_stack=...,
    with_flops=...,
    on_trace_ready=torch.profiler.tensorboard_trace_handler(...),
)
```

而它的 stop 逻辑还会导出一份表格：

```python
table = self.profiler.key_averages().table(sort_by="self_cuda_time_total")
```

这意味着 vLLM 的 torch profiler 不只是导出 trace，还会顺手输出一份按 CUDA 时间排序的汇总表，方便先做快速筛查。

**4. 每个 worker step 都会打 record_function 标记**

`Worker.annotate_profile()` 会这样写：

```python
self.profiler.step()
return self.profiler.annotate_context_manager(
    f"execute_new_{num_new}_cached_{num_cached}"
)
```

而 `TorchProfilerWrapper.annotate_context_manager()` 返回的是：

```python
return torch.profiler.record_function(name)
```

所以在 profiler trace 里，你会看到类似：

```text
execute_new_4_cached_12
```

这样的迭代级标记。这个细节很有用，因为它能帮你快速把 trace 对齐到 scheduler iteration，而不是只盯着零散 kernel。

**5. `layerwise_profile` 提供了按模块聚合的二次视图**

`profiler/layerwise_profile.py` 定义了：

```python
class layerwise_profile(profile):
    ...
    self.results = LayerwiseProfileResults(...)
```

它会在结束时构建：

- `_module_tree`
- `_model_stats_tree`
- `_summary_stats_tree`

然后支持：

- `print_model_table()`
- `print_summary_table()`
- `export_*_csv()`

所以如果普通 PyTorch Profiler 让你面对的是“原始事件时间线”，那么 `layerwise_profile` 提供的是：

**更接近‘模型层级’而不是‘单个 op’的解释视图。**

### 代码示例

下面给一个最小的 torch profiler 配置示例：

```python
from vllm import LLM

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    profiler_config={
        "profiler": "torch",
        "torch_profiler_dir": "/tmp/vllm_torch_profiler",
        "torch_profiler_with_stack": True,
        "torch_profiler_record_shapes": True,
        "delay_iterations": 5,
        "max_iterations": 20,
    },
)
```

如果你是直接在源码层分析某个模块，也可以用 `layerwise_profile`：

```python
from vllm.profiler.layerwise_profile import layerwise_profile

with layerwise_profile(num_running_seqs=8) as prof:
    output = model(input_ids=input_ids, positions=positions)

prof.results.print_model_table()
prof.results.print_summary_table()
```

### 流程图

```text
                 vLLM 中的 PyTorch Profiler 路径
========================================================================

ProfilerConfig(profiler="torch")
   |
   v
Worker -> TorchProfilerWrapper
   |
   +--> start()
   +--> step()
   +--> record_function("execute_new_X_cached_Y")
   +--> stop()
   |
   +--> TensorBoard trace
   +--> key_averages table
   +--> (可选) layerwise_profile 二次聚合
```

## 18.2 vLLM 使用 NVIDIA Nsight Systems 进行性能分析

### 原理讲解

如果 PyTorch Profiler 更擅长回答“哪类 op 慢”，那么 Nsight Systems 更擅长回答：

1. **CPU 和 GPU 时间线是怎么交错的？**
2. **kernel launch、通信、同步、NVTX 区间之间的因果关系是什么？**
3. **到底是 GPU 算慢了，还是 CPU、调度、同步把 GPU 饿住了？**

Nsight Systems 更像“系统级时间线放大镜”。

它特别适合看：

- GPU 空洞
- kernel launch 间隙
- CUDA stream 并行情况
- NVTX 标注下的层级执行范围

### 源码解析

**1. vLLM 提供了 CUDA profiler 包装，方便和 Nsight 配合**

在 `CudaProfilerWrapper` 里：

```python
import torch.cuda.profiler as cuda_profiler
...
self._cuda_profiler.start()
self._cuda_profiler.stop()
```

这意味着当 `profiler_config.profiler == "cuda"` 时，vLLM 可以通过 CUDA Profiler API 显式给出 profile capture 的起止边界。

这对 Nsight Systems 很有用，因为它正好可以和：

```text
--capture-range=cudaProfilerApi
```

这类用法配合。

**2. iteration 级 NVTX 标记来自 `annotate_context_manager()`**

`CudaProfilerWrapper.annotate_context_manager()` 返回：

```python
return torch.cuda.nvtx.range(name)
```

而 `Worker.annotate_profile()` 传入的是：

```python
f"execute_new_{num_new}_cached_{num_cached}"
```

所以在 Nsight 时间线上，至少可以看到 worker iteration 粒度的 NVTX range。

**3. 更细粒度的 layerwise NVTX tracing 来自 `ObservabilityConfig`**

`config/observability.py` 里：

```python
enable_layerwise_nvtx_tracing: bool = False
```

注释已经写明：

- 这会为每层 / 模块打 NVTX 标记
- 但和 CUDA graphs 不兼容

**4. 具体的 NVTX 标记实现位于 `nvtx_pytorch_hooks.py`**

这里的 `construct_marker_dict_and_push()` 会把下面这些信息放进 NVTX marker：

- module 名称
- trainable params 形状
- input tensor shapes
- output tensor shapes
- 一些静态层参数

例如对 `Linear`，它会记录：

```python
param_info["in_features"] = module_obj.in_features
param_info["out_features"] = module_obj.out_features
```

这意味着开启 layerwise NVTX tracing 后，Nsight 时间线里的 marker 不只是名字，还会携带一部分结构化上下文。

### 代码示例

下面给出一个适合和 Nsight Systems 配合的配置示例：

```python
from vllm import LLM

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    profiler_config={
        "profiler": "cuda",
        "delay_iterations": 10,
        "max_iterations": 30,
    },
    compilation_config={
        "mode": "NONE",
    },
    observability_config={
        "enable_layerwise_nvtx_tracing": True,
    },
)
```

然后用 Nsight Systems 运行：

```bash
nsys profile \
  --trace=cuda,nvtx,osrt \
  --capture-range=cudaProfilerApi \
  --output=/tmp/vllm_nsys \
  python your_vllm_script.py
```

这个组合的含义是：

- `profiler="cuda"`：由 vLLM 触发 `cudaProfilerStart/Stop`
- `--capture-range=cudaProfilerApi`：Nsight 只采集你真正关心的区间
- `enable_layerwise_nvtx_tracing=True`：在时间线上看到模块级 NVTX marker

### 数据流图

```text
              vLLM + Nsight Systems 的典型配合方式
========================================================================

ProfilerConfig(profiler="cuda")
   |
   v
CudaProfilerWrapper.start()/stop()
   |
   +--> CUDA Profiler API capture range
   |
Worker.annotate_profile()
   |
   +--> iteration 级 NVTX range
   |
ObservabilityConfig.enable_layerwise_nvtx_tracing
   |
   +--> nvtx_pytorch_hooks.py
   +--> layer/module 输入输出与静态参数标记
   |
   v
Nsight Systems timeline
```

## 总结

1. PyTorch Profiler 更适合分析 op 级和模块级耗时，Nsight Systems 更适合分析系统级时间线和 CPU/GPU 协同问题。
2. `ProfilerConfig` 是统一入口，worker 侧通过 `TorchProfilerWrapper` 或 `CudaProfilerWrapper` 真正落地 profiler 生命周期。
3. `Worker.annotate_profile()` 会为每个 iteration 打标签，这让 trace 更容易和 vLLM 调度轮次对齐。
4. `layerwise_profile` 在普通 profiler 之上又做了一层模块树聚合，适合快速定位“哪一层最慢”。
5. `enable_layerwise_nvtx_tracing` + `nvtx_pytorch_hooks.py` 让 Nsight 时间线具备更强的可读性，但当前源码也明确提示它不适合与 CUDA graphs 同开。
6. 选工具时要先分清你要回答的问题：看算子分布优先 PyTorch Profiler，看系统级时间线和 GPU 空洞优先 Nsight Systems。
