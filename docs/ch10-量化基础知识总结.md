## 10.1 模型量化原理

### 原理讲解

模型量化的目标很简单：

**把原本用高精度浮点数存储和计算的权重/激活，改成更低比特的表示，从而减少显存和带宽开销。**

它最常见的收益有三个：

1. **模型权重更省显存**
2. **访存带宽压力下降**
3. **在支持相应 kernel 的硬件上，矩阵乘法可以更快**

但量化也一定会带来信息损失。因为原本连续的高精度数值，被映射到了更稀疏、更短的离散表示里。

从工程角度看，量化一般可以按两个维度来理解：

**第一维：量化对象**

- 只量化权重：weight-only quantization
- 同时量化权重和激活：W8A8 / FP8 等

**第二维：量化时机**

- 离线量化：checkpoint 本身就是量化好的
- 在线量化：先加载高精度权重，再在加载后转成量化格式

### 源码解析

在 vLLM 里，量化不是某个零散优化，而是一个完整模块体系。最顶层入口在：

```python
# vllm/vllm/model_executor/layers/quantization/__init__.py
QuantizationMethods = Literal[
    "awq", "fp8", "fp_quant", "gptq", "bitsandbytes", "torchao", ...
]
```

这说明 vLLM 把“量化方法”当成一种一等公民配置项。

而真正的统一抽象在 `base_config.py`：

```python
class QuantizeMethodBase(ABC):
    def create_weights(...)
    def apply(...)


class QuantizationConfig(ABC):
    def get_name(...)
    def get_supported_act_dtypes(...)
    def get_min_capability(...)
    def from_config(...)
    def get_quant_method(...)
```

这个抽象非常重要，因为它把量化拆成了两层：

- `QuantizationConfig`：负责解释“当前量化方法是什么、支持什么配置”
- `QuantizeMethodBase`：负责解释“某个具体层怎么创建量化权重、怎么执行”

因此 vLLM 的量化设计不是“到处 if quantization == xxx”，而是统一走配置对象和层方法对象。

### 代码示例

下面用一个最小的仿射量化例子说明量化最基本的数学过程：

```python
import torch


def fake_quantize(x, num_bits=8):
    qmin = -(2 ** (num_bits - 1))
    qmax = 2 ** (num_bits - 1) - 1
    scale = x.abs().max() / qmax
    q = torch.clamp(torch.round(x / scale), qmin, qmax)
    x_hat = q * scale
    return q, scale, x_hat


x = torch.tensor([0.1, -0.7, 2.3, 5.8])
q, scale, x_hat = fake_quantize(x)
print("原始值:", x)
print("量化值:", q)
print("缩放因子:", scale)
print("反量化值:", x_hat)
```

这个例子里最重要的不是精度，而是这三个角色：

- `q`：低比特离散值
- `scale`：缩放因子
- `x_hat`：反量化后的近似值

## 10.2 什么是定点数和浮点数

### 原理讲解

理解量化时，最容易混淆的就是“定点数”和“浮点数”。

**定点数（fixed-point）** 的特点是：

- 小数点位置是固定的
- 需要一个外部 scale 来解释整数值
- 实现简单，适合 INT8 / INT4 这类量化

**浮点数（floating-point）** 的特点是：

- 数值写成“符号 + 指数 + 尾数”
- 可以同时表示很小和很大的数
- 动态范围更大，但硬件和 kernel 支持要求更高

如果只从直觉上理解：

- 定点量化更像“所有数都按同一把尺子压缩”
- 浮点量化更像“每个数自带一个粗粒度的尺度信息”

### 源码解析

vLLM 里的这两类差异，在具体权重格式上非常明显。

**1. AWQ 属于典型的低比特定点权重量化**

在 `awq.py` 里，`AWQLinearMethod.create_weights()` 注册了：

```python
layer.register_parameter("qweight", qweight)
layer.register_parameter("qzeros", qzeros)
layer.register_parameter("scales", scales)
```

这正是定点量化的经典三件套：

- `qweight`：低比特整数权重，实际存成打包后的 `int32`
- `qzeros`：zero point
- `scales`：缩放因子

**2. FP8 则属于浮点量化路线**

在 `fp8.py` 里，`Fp8Config` 会根据配置选择：

- `activation_scheme = static / dynamic`
- `weight_block_size`
- per-tensor 或 block-wise 的缩放方式

并且它支持的激活 dtype 是：

```python
@classmethod
def get_supported_act_dtypes(cls) -> list[torch.dtype]:
    return [torch.bfloat16, torch.half]
```

说明 FP8 并不是“所有东西都直接变成 8 bit”，而是通常结合更高精度激活、缩放因子和硬件 kernel 一起使用。

### 代码示例

下面用 `math.frexp` 演示“浮点数里指数和尾数是分开的”这个概念：

```python
import math


values = [0.125, 1.5, 10.0, 123.0]
for v in values:
    mantissa, exponent = math.frexp(v)
    print(f"value={v}, mantissa={mantissa}, exponent={exponent}")
```

这个输出说明：

- 浮点数不是简单“存一个整数然后乘固定 scale”
- 而是“尾数 x 2^指数”的表示形式

如果对应到量化世界：

- INT4/INT8 更偏定点逻辑
- FP8/FP4 更偏低比特浮点逻辑

## 10.3 浮点量化方法的改进

### 原理讲解

传统 INT8 / INT4 量化很省，但也有两个常见问题：

1. **动态范围不够灵活**
2. **某些层对量化误差更敏感**

因此，大模型推理里出现了两类改进方向：

**方向一：低比特浮点**

- FP8
- FP4

它们保留了“指数 + 尾数”的思路，动态范围通常比纯整数更灵活。

**方向二：更细粒度的缩放**

- per-tensor
- per-channel
- group-wise
- block-wise

它们的核心不是换表示法，而是换“每一把尺子的覆盖范围”。

### 源码解析

vLLM 在 `Fp8Config` 里直接把这些改进点暴露成了配置：

```python
class Fp8Config(QuantizationConfig):
    def __init__(
        self,
        is_checkpoint_fp8_serialized=False,
        activation_scheme="dynamic",
        ignored_layers=None,
        weight_block_size=None,
    ):
        ...
```

这里至少对应三件事：

- `activation_scheme`：激活量化是静态还是动态
- `ignored_layers`：哪些层不要量化
- `weight_block_size`：是否走 block-wise 权重量化

再看 `Fp8LinearMethod.__init__()`：

```python
self.weight_block_size = self.quant_config.weight_block_size
self.block_quant = self.weight_block_size is not None
...
if self.block_quant:
    self.w8a8_block_fp8_linear = W8A8BlockFp8LinearOp(...)
else:
    self.fp8_linear = Fp8LinearOp(...)
```

这说明在工程上，FP8 不是一个单一实现，而是至少分成：

- 普通 per-tensor/per-token 路线
- block quant 路线

`fp_quant.py` 则展示了更激进的低比特浮点思路：

```python
class FPQuantConfig(QuantizationConfig):
    def __init__(
        self,
        hadamard_group_size=32,
        forward_dtype="mxfp4",
        forward_method="abs_max",
        ...
    ):
        ...
```

这里的 `mxfp4` / `nvfp4` 就已经不再是传统 INT 量化了，而是在更低 bit 的浮点格式上继续做工程化。

### 代码示例

下面用一个 block-wise scale 的最小例子说明“更细粒度缩放”的直觉：

```python
import torch


def blockwise_fake_quant(x, block_size=4):
    x = x.clone()
    blocks = x.view(-1, block_size)
    scales = blocks.abs().amax(dim=1, keepdim=True).clamp_min(1e-6) / 127
    q = torch.round(blocks / scales).clamp(-127, 127)
    x_hat = q * scales
    return q, scales, x_hat


x = torch.tensor([0.1, 0.2, 0.3, 0.4, 3.0, 4.0, 5.0, 6.0])
q, scales, x_hat = blockwise_fake_quant(x, block_size=4)
print("块缩放:", scales.view(-1))
print("反量化:", x_hat.view(-1))
```

这个例子说明：

- 前 4 个值用一把尺子
- 后 4 个值用另一把尺子

相比整张量一把尺子，这样通常更容易兼顾大值和小值。

## 10.4 大模型中的量化算法 - AWQ

### 原理讲解

AWQ 全称是 **Activation-aware Weight Quantization**。

它最核心的思想不是“盲目把所有权重都压成 4 bit”，而是：

**利用激活分布信息，尽量保护对输出更敏感的权重通道，再对权重做低比特量化。**

因此 AWQ 经常被归类为：

- 大模型里很典型的 weight-only quantization
- 兼顾效果和部署实用性的 4bit 路线

从工程角度看，AWQ 常常有几个特点：

1. 权重是 INT4 一类的低比特格式
2. 通常按 group 做量化
3. 推理时需要配套 kernel 来高效解包和 GEMM

### 源码解析

vLLM 里的 `AWQConfig` 已经把这些核心参数体现出来了：

```python
class AWQConfig(QuantizationConfig):
    def __init__(self, weight_bits, group_size, zero_point, ...):
        ...
        self.pack_factor = 32 // self.weight_bits
```

这里的 `pack_factor` 说明了一个很实际的工程事实：

**INT4 权重不会按“一个 weight 一个 4bit 对象”来存，而是打包进更宽的整数里。**

再看 `AWQLinearMethod.create_weights()`：

```python
layer.register_parameter("qweight", qweight)
layer.register_parameter("qzeros", qzeros)
layer.register_parameter("scales", scales)
```

这说明 AWQ 在 vLLM 里的权重形式非常明确：

- `qweight`：打包后的量化权重
- `qzeros`：零点
- `scales`：每组缩放因子

最后看执行路径：

```python
if FP16_MATMUL_HEURISTIC_CONDITION:
    out = ops.awq_dequantize(qweight, scales, qzeros, 0, 0, 0)
    out = torch.matmul(reshaped_x, out)
else:
    out = ops.awq_gemm(reshaped_x, qweight, scales, qzeros, pack_factor)
```

这段代码非常值得记住，因为它说明 AWQ 推理时不一定只走一种 kernel：

- token 很多时，可能先反量化再 matmul
- token 较少时，直接走专用 `awq_gemm`

也就是说，AWQ 在工程里不只是“一个 checkpoint 格式”，而是一整套：

**量化权重布局 + 缩放参数 + 推理 kernel 选择策略。**

### 代码示例

下面给一个教学版 group quantization 例子，帮助理解 `group_size` 的含义：

```python
import torch


def group_quantize(weight, group_size=4):
    weight = weight.clone()
    groups = weight.view(-1, group_size)
    scales = groups.abs().amax(dim=1, keepdim=True).clamp_min(1e-6) / 7
    q = torch.round(groups / scales).clamp(-8, 7).to(torch.int32)
    return q, scales


w = torch.tensor([
    0.1, 0.2, -0.4, 0.8,
    2.0, -1.0, 1.5, -2.5,
], dtype=torch.float32)

q, scales = group_quantize(w, group_size=4)
print("qweight:", q)
print("scales:", scales.view(-1))
```

这个例子虽然没有实现 AWQ 的激活感知搜索，但已经体现了两个最核心的工程概念：

- 低比特整数权重
- 分组缩放因子

## 总结

1. 量化的本质是用更低比特表示权重和激活，以换取更低显存、更低带宽和更高吞吐
2. vLLM 用 `QuantizationConfig` 和 `QuantizeMethodBase` 把各种量化方法统一到了同一套抽象之下
3. 定点量化和浮点量化的根本区别在于：前者依赖外部 scale，后者自带指数和尾数结构
4. 浮点量化的改进方向主要有两条：更低比特浮点格式，以及更细粒度的缩放策略
5. AWQ 是大模型里很典型的 4bit weight-only 路线，在 vLLM 里对应 `qweight/qzeros/scales + awq_gemm`
6. 真正落地时，量化从来不只是一个数学公式，还包括权重布局、缩放参数、kernel 选择和硬件能力约束
