## 13.1 AllReduce 原理

### 原理讲解

张量并行的本质是：

**把同一个层的参数拆到多张卡上，再通过通信把各卡的局部结果拼成完整结果。**

这里最核心的通信原语就是 `AllReduce`。

它的定义可以简单理解为：

- 每个 rank 都有一份局部张量
- 先按某种规约方式做聚合，通常是 `sum`
- 再把聚合结果分发回所有 rank

在 Transformer 推理里，`AllReduce` 最典型的用途是：

1. **Row Parallel 输出求和**
2. **Vocab Parallel Embedding 输出求和**
3. 某些 TP 场景下把局部 partial result 还原成完整隐藏状态

如果进一步展开，`AllReduce` 常被实现为：

1. `ReduceScatter`
2. `AllGather`

所以你会经常看到 TP 代码里不止有 `all_reduce`，还会出现：

- `all_gather`
- `reduce_scatter`

它们本质上是同一类“张量并行通信积木”的不同组合。

### 源码解析

**1. TP group 在 `initialize_model_parallel()` 里建立**

```python
# vllm/vllm/distributed/parallel_state.py
all_ranks = torch.arange(world_size).reshape(
    -1,
    data_parallel_size,
    pipeline_model_parallel_size,
    prefill_context_model_parallel_size,
    tensor_model_parallel_size,
)
group_ranks = all_ranks.view(-1, tensor_model_parallel_size).unbind(0)
_TP = init_model_parallel_group(group_ranks, ..., group_name="tp")
```

这说明：

- TP 不是运行时临时拼出来的
- 它在分布式初始化阶段就已经固定成了一个通信组

后面所有 `tensor_model_parallel_*` 操作，本质上都只在这个 `_TP` group 内发生。

**2. 通信操作统一收口在 `communication_op.py`**

```python
def tensor_model_parallel_all_reduce(input_: torch.Tensor) -> torch.Tensor:
    return get_tp_group().all_reduce(input_)

def tensor_model_parallel_all_gather(input_: torch.Tensor, dim: int = -1) -> torch.Tensor:
    return get_tp_group().all_gather(input_, dim)

def tensor_model_parallel_reduce_scatter(input_: torch.Tensor, dim: int = -1) -> torch.Tensor:
    return get_tp_group().reduce_scatter(input_, dim)
```

这一层非常薄，但意义很大：

- 上层线性层、embedding 层不需要关心具体 NCCL / ProcessGroup 细节
- 只需要表达“这里需要 TP all_reduce”即可

**3. `AllReduce` 在 TP 里通常对应“把各 rank 的 partial sum 汇总”**

以 `RowParallelLinear.forward()` 为例：

```python
output_parallel = self.quant_method.apply(self, input_parallel, bias_)

if self.reduce_results and self.tp_size > 1:
    output = tensor_model_parallel_all_reduce(output_parallel)
else:
    output = output_parallel
```

这里每个 rank 只持有一部分输入维度和一部分权重，因此算出来的是局部贡献：

```text
Y_local = X_i * A_i
```

要得到完整的 `Y = Σ X_i A_i`，就必须做一次 `AllReduce(sum)`。

### 代码示例

下面用一个两卡例子模拟 `AllReduce(sum)` 的含义：

```python
rank0_partial = [1.0, 2.0, 3.0]
rank1_partial = [10.0, 20.0, 30.0]

full = [a + b for a, b in zip(rank0_partial, rank1_partial)]

print("rank0 partial:", rank0_partial)
print("rank1 partial:", rank1_partial)
print("allreduce(sum):", full)
```

输出结果可以理解成：

- 每张卡各自产生了一部分结果
- 通信之后，每张卡都拿到了完整结果

### 流程图

```text
                 TP 中 AllReduce 的角色
=================================================================

rank0: partial_output_0  ----\
                              +--> AllReduce(sum) --> full_output
rank1: partial_output_1  ----/

常见来源:
- RowParallelLinear 的局部矩阵乘结果
- VocabParallelEmbedding 的局部 embedding 查表结果
- 某些 TP combine 阶段的局部 hidden states
```

## 13.2 Transformer 模型的张量并行

### 原理讲解

Transformer 里的不同子层，适合的切分方式并不一样。

最常见的三种 TP 方式是：

1. **列并行（Column Parallel）**
2. **行并行（Row Parallel）**
3. **词表并行（Vocab Parallel）**

它们分别适合：

- `QKV / gate_proj / up_proj`：列并行
- `o_proj / down_proj`：行并行
- `Embedding / LM Head`：词表并行

原因很简单：

**你要让“切分后的局部计算”尽量自然。**

例如：

- 对 `Y = XA`，如果按 `A` 的列切，就是 `A = [A1, A2, ..., Ap]`
- 那么每个 rank 都可以独立算 `Y_i = X A_i`
- 最终如果需要完整输出，再做 `AllGather`

而如果按 `A` 的行切：

- `A` 的输入维度被拆开
- 输入 `X` 也要相应切片
- 每个 rank 算的是局部加和项
- 最后需要 `AllReduce`

### 源码解析

**1. `ColumnParallelLinear` 按输出维度切权重**

```python
self.output_size_per_partition = divide(output_size, self.tp_size)
output_parallel = self.quant_method.apply(self, input_, bias)
if self.gather_output and self.tp_size > 1:
    output = tensor_model_parallel_all_gather(output_parallel)
```

这说明列并行的特点是：

- 每个 rank 都拿完整输入 `X`
- 每个 rank 只计算自己那一列权重对应的输出分片
- 若调用方只需要局部 shard，可以不 gather
- 若调用方需要完整输出，再执行 `all_gather`

这非常适合：

- Q 投影
- K 投影
- V 投影
- MLP 的 gate / up 投影

**2. `QKVParallelLinear` 是列并行的一个特殊版本**

`QKVParallelLinear` 继承自 `ColumnParallelLinear`，但多做了两件事：

1. 按 attention head 粒度切 Q/K/V
2. 处理 GQA / MQA 里 `KV head` 数量小于 `TP size` 的情况

源码里有一个很关键的变量：

```python
self.num_kv_head_replicas = divide(self.tp_size, self.total_num_kv_heads)
```

这意味着当 `tp_size > total_num_kv_heads` 时：

- Query 头继续按 TP 切分
- KV 头会发生复制，而不是继续硬切

这正是 GQA/MQA 模型在 TP 场景下必须处理的细节。

**3. `RowParallelLinear` 按输入维度切权重**

```python
self.input_size_per_partition = divide(input_size, self.tp_size)

if self.input_is_parallel:
    input_parallel = input_
else:
    input_parallel = split_tensor_along_last_dim(input_, num_partitions=self.tp_size)[self.tp_rank]

output_parallel = self.quant_method.apply(self, input_parallel, bias_)
output = tensor_model_parallel_all_reduce(output_parallel)
```

这里要注意两个点：

- 权重是沿输入维度切的
- 输入也要相应切分

因此每个 rank 只算一部分贡献，最后必须做 `AllReduce`。

这特别适合：

- Attention 的 `o_proj`
- MLP 的 `down_proj`

因为它们都要把多个分片“加回去”。

**4. `VocabParallelEmbedding` 按词表维度切**

```python
masked_input, input_mask = get_masked_input_and_mask(...)
output_parallel = self.quant_method.embedding(self, masked_input.long())
output_parallel.masked_fill_(input_mask.unsqueeze(-1), 0)
output = tensor_model_parallel_all_reduce(output_parallel)
```

它的思路是：

- 每个 rank 只保存一段词表
- 如果输入 token 不属于当前 rank 的词表范围，就把它 mask 掉
- 本地查表后，对无效 token 的输出置 0
- 最后通过 `AllReduce(sum)` 把真正命中的那份 embedding 汇总回来

这和 `RowParallelLinear` 一样，都是“局部有值，其它 rank 为 0，再求和”的模式。

### 代码示例

下面用一个最小例子说明列并行和行并行的差异：

```python
x = [1, 2]

# 列并行: A = [A0 | A1]
A0 = [[1, 0], [0, 1]]
A1 = [[2, 0], [0, 2]]

y0 = [x[0] * 1 + x[1] * 0, x[0] * 0 + x[1] * 1]
y1 = [x[0] * 2 + x[1] * 0, x[0] * 0 + x[1] * 2]
print("column parallel shards:", y0, y1)

# 行并行: A = [A0; A1]
x0 = [1]
x1 = [2]
A0_row = [[1, 3]]
A1_row = [[10, 20]]

partial0 = [x0[0] * 1, x0[0] * 3]
partial1 = [x1[0] * 10, x1[0] * 20]
full = [partial0[0] + partial1[0], partial0[1] + partial1[1]]
print("row parallel partials:", partial0, partial1)
print("row parallel allreduce result:", full)
```

### 数据流图

```text
               Transformer 中最常见的 TP 切分方式
========================================================================

hidden_states
   |
   +--> QKVParallelLinear
   |      - 列并行
   |      - 每个 rank 负责一部分 q/k/v heads
   |
   +--> Attention
   |
   +--> o_proj
   |      - RowParallelLinear
   |      - 每个 rank 先算局部贡献，再 AllReduce
   |
   +--> gate_up_proj
   |      - MergedColumnParallelLinear
   |
   +--> down_proj
          - RowParallelLinear
          - 再次 AllReduce

embedding / lm_head
   - VocabParallelEmbedding / ParallelLMHead
   - 词表维度切分
```

## 13.3 vLLM 中的张量并行

### 原理讲解

把 TP 放回 vLLM 的整体架构里，可以把它理解成三件事：

1. **初始化阶段创建 TP 通信组**
2. **模型加载阶段按 TP rank 切权重**
3. **执行阶段在特定层插入 TP 通信**

也就是说，vLLM 的 TP 不是“请求级切分”，而是：

**同一个请求进入多个 worker，每个 worker 持有同一层的不同参数分片。**

因此 TP 的主要收益是：

- 单卡权重显存下降
- 可以承载更大的模型

它的主要代价是：

- 每层 forward 会有跨卡通信
- TP 越大，通信开销越明显

### 源码解析

**1. 配置入口是 `tensor_parallel_size`**

```python
# vllm/vllm/config/parallel.py
class ParallelConfig:
    tensor_parallel_size: int = 1
```

用户在离线或在线场景里设置：

```python
LLM(model=..., tensor_parallel_size=2)
```

或者：

```bash
vllm serve MODEL --tensor-parallel-size 2
```

都会最终进入同一个 `ParallelConfig`。

**2. vLLM 在分布式初始化时创建 TP group**

`parallel_state.initialize_model_parallel()` 会把完整世界切成多种 group，其中 TP group 是最基础的一类：

```python
_TP = init_model_parallel_group(group_ranks, ..., group_name="tp")
```

后续层里通过：

```python
get_tensor_model_parallel_rank()
get_tensor_model_parallel_world_size()
```

来拿到当前 rank 所属的 TP 信息。

**3. 层在构造时就根据 `tp_rank / tp_size` 决定参数分片形状**

例如 `ColumnParallelLinear.__init__()`：

```python
self.tp_rank = get_tensor_model_parallel_rank()
self.tp_size = get_tensor_model_parallel_world_size()
self.output_size_per_partition = divide(output_size, self.tp_size)
```

例如 `RowParallelLinear.__init__()`：

```python
self.input_size_per_partition = divide(input_size, self.tp_size)
```

这意味着权重不是等 forward 再切，而是在层初始化和权重加载阶段就已经被切成了本 rank 该持有的形状。

**4. 权重加载时也会按 TP shard 切 checkpoint**

以 `ColumnParallelLinear.weight_loader()` 为例：

```python
shard_size = param_data.shape[output_dim]
start_idx = self.tp_rank * shard_size
loaded_weight = loaded_weight.narrow(output_dim, start_idx, shard_size)
```

这段逻辑的含义是：

- checkpoint 里通常是完整权重
- vLLM 加载时只截取当前 TP rank 对应的切片

**5. 执行阶段由 `ModelRunner` 驱动整张 TP 模型前向**

从更高一层看，请求还是由 `GPUModelRunner.execute_model()` 驱动整张模型执行。

只是模型内部的某些模块在 forward 时会：

- 自动读取本 TP rank 的分片权重
- 在需要的节点插入 `all_gather` / `all_reduce`

所以 vLLM 的 TP 可以理解为：

**由模型层自己封装通信，`ModelRunner` 只负责正常调用 `model(...)`。**

### 代码示例

下面给出一个最小的 vLLM TP 启动示例：

```python
from vllm import LLM

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    tensor_parallel_size=2,
)

outputs = llm.generate("Explain tensor parallelism in one paragraph.")
print(outputs[0].outputs[0].text)
```

在线服务场景的命令形式也类似：

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --tensor-parallel-size 2
```

### 完整流程图

```text
                    vLLM 中 TP 的工作路径
============================================================================

用户配置 tensor_parallel_size=2
   |
   v
ParallelConfig
   |
   v
init_distributed_environment()
   |
   v
initialize_model_parallel()
   |
   +--> 建立 TP group
   |
   v
Worker / ModelRunner 加载模型
   |
   +--> ColumnParallel / RowParallel / VocabParallel 层按 tp_rank 建权重
   +--> weight_loader 只截 checkpoint 的本地 shard
   |
   v
forward
   |
   +--> 列并行层: 局部 GEMM -> 需要时 AllGather
   +--> 行并行层: 局部 GEMM -> AllReduce
   +--> 词表并行层: 本地查表 -> AllReduce
   |
   v
得到完整 hidden_states / logits
```

## 总结

1. 张量并行的核心不是“多卡同时跑”，而是“同一层参数被切到多卡，再通过通信恢复完整结果”。
2. `AllReduce` 在 TP 里主要用于 `RowParallelLinear` 和 `VocabParallelEmbedding` 这类“局部求和”场景。
3. `ColumnParallelLinear` 适合 QKV 和 MLP 上投影，`RowParallelLinear` 适合 attention 输出投影和 MLP 下投影。
4. `QKVParallelLinear` 额外处理了 GQA / MQA 模型里的 KV head 切分与复制问题。
5. vLLM 在初始化阶段就创建 TP group，在权重加载阶段就完成 shard 切分，在执行阶段由层自己封装通信。
6. TP 能显著降低单卡权重显存，但随着 TP size 增大，跨卡通信成本也会明显上升。
